# Security Policy

## Reporting a vulnerability

Please do not open a public issue for a suspected security vulnerability.

Instead, contact the repository owner privately with:

- the affected component or endpoint;
- steps to reproduce the issue;
- the potential impact;
- any logs or proof-of-concept material with secrets removed.

Avoid including API keys, credentials, tokens, personal data, or production secrets in reports.

## Scope

Security reports involving authentication, authorization, telemetry ingestion, WebSocket handling, deployment configuration, or sensitive diagnostic data are especially useful.

Please allow time for the issue to be reproduced and assessed before public disclosure.
