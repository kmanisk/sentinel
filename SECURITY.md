# Security Policy

## Reporting a vulnerability

Please do not open a public issue for a suspected security vulnerability.

Instead, contact the repository owner privately with:

- the affected component or endpoint;
- steps to reproduce the issue;
- the potential impact;
- any logs or proof-of-concept material with secrets removed.

Avoid including API keys, credentials, tokens, personal data, or production secrets in reports.

## Scope

Security reports involving authentication, authorization, telemetry ingestion, WebSocket handling, deployment configuration, or sensitive diagnostic data are especially useful.

## Response and disclosure

Reports should include enough detail to reproduce the issue safely. After a report is received, the issue should be reproduced, its impact assessed, and a remediation plan prepared before public disclosure.

Please avoid publishing exploit details while a fix is being developed. Once a fix is available, disclosure can include the affected versions, impact, mitigation, and upgrade guidance without exposing secrets or unrelated user data.
