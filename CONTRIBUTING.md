# Contributing

Contributions are welcome. Security- or monitoring-related changes should be narrowly scoped and clearly describe any new privileges, data collection, or external communication.

## Workflow

1. Branch from `main`.
2. Follow the setup and run instructions in `README.md`.
3. Keep each pull request limited to one logical change.
4. Run the relevant formatter, linter, build, and tests available in the repository.
5. Describe the behavior change, security implications, and verification performed.

Do not commit credentials, tokens, personal logs, captured user data, machine-specific state, generated build output, or local caches. Redact sensitive information from bug reports and diagnostics.
